# メインメニュー上下の右端が見切れる原因

調査日：2026-11-26。修正・再ビルド・ゲームへの再適用は行っていない。

## 結論

日本語でボタンの最小幅が増え、上下バーの最小幅の合計が画面内の論理幅を超えている。
バーは横一列の `HBoxContainer` で、折り返し・縮小・省略表示によって幅を収める処理がない。
固定幅の領域と余白を残したまま、右側へはみ出す。

標準の UI 倍率 `1.4` では、1920×1080 の基準画面の論理幅は約 `1371.429`。
同じ条件で英語版は収まるが、日本語版は上下とも超過した。

| バー | 英語版の最小幅 | 日本語版の最小幅 | 日本語版の超過 |
| --- | ---: | ---: | ---: |
| 上部 | 1369 | 1480 | 約108.571 |
| 下部 | 1233 | 1415 | 約43.571 |

下部の測定条件は `captain`、`school`、`nationals`、時刻0。
導入済みゲームの保存設定でも、この服装・ボール・会場の組合せを確認した。
プレイヤー情報は隔離環境の新規プロフィールを使い、名前だけ `Player` に固定した。
実際の名前・レベル・XP・所持金で下部の幅は変動するため、この数値はユーザーの実画面そのものの測定ではない。

## 上部

復元した `work/recovered/game/ui/menu.gd` の該当箇所：

- `_bar_box()`（1993行）：左右余白28、通常の `HBoxContainer`、間隔14。
- `_tab()`（2055行）：ボタンの最小幅76、フォント17、左右余白各13。76は幅の上限ではない。
- `_build_bars()`（2079行）：ロゴの空き領域164を確保。
- 同関数（2124行）：パーティー枠に `PARTY_DOCK_W` を指定。定義は7895行の392。
- 余白用の `SIZE_EXPAND_FILL` は空きを配分するだけで、他のボタンの最小幅を縮めない。

日本語化後、例えばプロフィールのタブは79→128、ロッカーは76→94、実績は85→111に増える。
英語版でも残り幅は約2.429しかなく、日本語の幅増加を吸収できない。
測定時、日本語版の最後のボタンの右端は1452で、表示可能幅1371.429を越えた。

## 下部

同じ `_build_bars()` の2170行以降で、プレイヤーカード、Discord、服装、ボール、会場、
フリープレイ、バージョンを一列に追加している。間隔10、左右余白は28と18。
`_snug()`（2348行）は一部ボタンの左右余白を各12にするだけで、文字の長さを制限しない。

`translations/ja/ui.json` の以下の訳が、特に服装ボタンを長くする。

- `outfit: %s` → `ユニフォーム：%s`
- `captain uniform` → `キャプテンのユニフォーム`

測定した服装ボタンは184→309、ボールは106→114、会場は182→189に増えた。
下部の最後の要素の右端は1397で、表示可能幅を越えた。
一方、初期服装 `gym`・ボール `nationals` では日本語版の下部最小幅は1295で収まった。
下部の症状が選択内容によって変わるのは、この動的な文字幅が原因。
マッチメイキング中は追加のラベルとキャンセルボタンが表示されるため、別途検証が必要。

## 日本語化側で対応していない点

`tools/build_patch.py` はフォーマット文字列と選択値の翻訳を追加するが、バーのレイアウトは変更しない。
`mod/bootstrap.gd` は翻訳登録と日本語フォントのフォールバックを追加するが、幅の調整は行わない。
したがって、日本語文字列の組版に合わせてボタンの最小幅が増えた際に、元の横一列レイアウトの余裕不足が表面化する。
フォント欠落やPCKの破損を原因とする結果ではない。

## 確認方法と修正の方向

元のバックアップPCKと現在導入済みの日本語PCKから、隔離した診断用PCKを作成。
元のメニュースクリプトを継承した診断シーンから `_build_bars()` を呼び出し、
通常のメニュー初期化・3Dシーン・オンライン参加処理は実行せず、バーの組版を測定した。
各倍率で12フレーム待った後に `get_combined_minimum_size()` と右端の座標を取得した。
最終測定は両言語とも終了コード0、スクリプトエラー0。
画面のスクリーンショットによる検証は行っていない。

倍率1.2（論理幅1600）、1.0（同1920）では、この測定条件の上下バーはいずれも収まった。
ただし固定倍率を下げるだけでは、長い名前や別の会場名への対応を保証できない。
修正は、上下バーを利用可能幅に合わせて再配置することを中心に、
服装の見出し・選択値の短縮や固定余白の見直しを組み合わせるのが適切。

測定結果は `evidence/menu-layout-investigation.json` に保存。
診断用スクリプト・PCK・ログは非追跡の `work/` に置いている。
