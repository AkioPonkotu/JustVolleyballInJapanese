# コントローラ設定のカード右端が見切れる原因

調査日：2026-11-27。ゲーム・配布パッチ・翻訳は変更していない。

## 結論

P1ヘッダーの日本語化で内部レイアウトの必要幅がカード幅を超える。
下のプロフィール・デバイス・操作ボタンも同じ内部コンテナーの幅に広がるため、
カード右端でまとめて切れる。添付画像のヘッダーと下部ボタンの見切れ方に一致する。

導入済みPCKと元のバックアップPCKを使い、実際の `_page()`、`_build_configs()`、
`CfgPanel` の生成・描画更新による組版をヘッドレスで比較した。
基準画面1920×1080、標準UI倍率1.4、4人分のカード、P1のみ参加、名前Player、
キーボード＆マウス、隔離した新規プロフィールで測定。

| 対象（Godotの論理座標） | 英語版 | 日本語版 |
| --- | ---: | ---: |
| P1カードの幅 | 252 | 252 |
| ヘッダーの必要最小幅 | 215 | 269 |
| 内部Bodyの実幅 | 252 | 269 |
| host / ホストの幅 | 37 | 47 |
| party leader / パーティーリーダーの幅 | 82 | 126 |
| 下部ボタンの右端（カード左端から） | 240 | 257 |

日本語版ではBodyがカードより17広く、左右12の余白を取った下部ボタンの右端が
カード右端を5超える。倍率1.4ならカード幅約353px、ボタン右端の超過約7pxで、
添付画像の約353pxのカードと右側の見切れに整合する。
画像の実行時の解像度・倍率を直接取得した結果ではない。

## 実装上の原因

復元した `work/recovered/game/ui/cfg_panel.gd`：

- `_ready()`（107行）：`clip_contents = true`、カードの最小幅220。
- `_build()`（129行）：カード直下に通常の `Control`（Stack）を置き、
  その中に全面アンカーの `VBoxContainer`（Body）を置く。
- ヘッダーは左右12の余白と間隔8の `HBoxContainer`。
  P1、ホスト、ステータスを横並びにする。
- `_status`（197行）は文字サイズ14で、省略・クリップ・折り返しを指定していない。
- `_paint()`（808行）：P1に `party leader` を設定する。
  `translations/ja/panels.json` の訳で「パーティーリーダー」になる。
- 下部の行は同じBodyに置かれ、左右12の余白を取って横幅いっぱいに配置される。

通常のControlであるStackが内部Bodyの最小幅をカードへ伝えないため、
外側のカードの最小幅は220のまま、内部だけが269まで広がる。
外側のHBoxは4枚のカードに幅を割り当てるが、内部の幅不足を検知できない。
最後にカードの `clip_contents` によって、はみ出した文字とボタンの右枠が切り落とされる。

`menu.gd` の `_build_configs()` は左右余白126、カード間隔14、4枚横並び。
既存の `mod/menu_layout.gd` はメインメニューの上下バー用で、このカードは調整しない。

## 原因を切り分ける対照実験

日本語版のヘッダーについて、他の行を変更せずに次を測定した。

1. ステータス文字列だけを空にするとBody幅269→252、下部ボタン右端257→240。
2. ステータスにクリップ・末尾省略と横方向拡張を設定してもBody幅252に収まる。

「キーボードとマウス」や「称号なし」の文字列を変えずに下部の見切れが消えるため、
この再現条件ではヘッダーの必要幅超過が下部も巻き込む直接の原因と確認できる。

修正の方向は、ステータスに利用可能幅を割り当てて省略するか、ヘッダーの配置・文言を
見直すこと。Stack越しに最小幅を伝えるだけでは4枚の合計幅が増えるため、画面全体の
幅不足も検証する必要がある。クリップ解除だけでは隣のカードへ描画が重なる。
今回は調査のみで、製品への修正は行っていない。

## 再現

リポジトリのルートで実行：

```powershell
uv run --python 3.12 --with-requirements requirements.txt python tools/measure_config_layout.py
```

既存の `work/recovered/project.godot` と、既定のSteamゲームフォルダーにある
EXE・PCK・元PCKバックアップが必要。診断用PCK、EXE、ログは非追跡の
`work/validation/config-layout/{en,ja}/` に生成される。
各言語専用の隔離ユーザーディレクトリを指定し、通常メニューの初期化、
オンライン参加処理、ユーザーの既存セーブは使用しない。

測定結果：`evidence/config-layout-investigation.json`。
両言語とも終了コード0、実行時・スクリプトエラー0。
診断は実際のコンテナーの組版測定であり、実画面の目視検証や全UI倍率・全プロフィール・
全参加状態の網羅検証は含まない。
