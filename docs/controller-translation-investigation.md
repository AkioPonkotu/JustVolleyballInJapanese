# コントローラー設定の一覧が英語で残る原因

調査日：2026-11-27。添付画像の「あなたの設定」内の8項目と、下部の `change` を調査した。
今回は調査のみ。翻訳・パッチ生成処理・導入済みゲームは変更していない。

## 原因

設定名と値を翻訳する前に連結し、連結後の全文を Label の自動翻訳へ渡している。
辞書にある設定名単独のキーと一致しないため、英語のまま表示される。

復元元 `work/recovered/game/ui/cfg_panel.gd` の経路：

- 1314行 `_build_settings_list()`：`stick sens` などの設定名と、値を返す Callable を `_value_row()` へ渡す。
- 1234行 `_value_row()`：`"%s: %s" % [label, shown.call()]` で連結する。設定名と値に `tr()` はない。
- 1144行 `_list_row()`：連結済みの文字列を `l.text = text_in` で Label に設定する。
- 1240行：再表示用の `text_fn` も同じ英語の連結処理を持つ。
- 1253行 `_refresh_values()`：設定変更後は `text_fn` の返り値を Label へ設定する。

例えば辞書には `stick sens` → `スティック感度` があるが、表示時に渡る
`stick sens: 1.00x` はない。`invert x axis` と `off` にもそれぞれ訳があるが、
`invert x axis: off` 全体のキーはない。自動翻訳は文字列の部分ごとには置き換えない。

`tools/build_patch.py` の65～77行は、辞書に登録された書式付き文字列だけを
補間前に日本語へ置換する。共通書式 `%s: %s` は辞書に登録されていないため対象外であり、
この設定一覧に対する個別の補完処理もない。
共通書式だけを辞書に追加しても、引数の設定名と値は英語のまま残る。

## 下部の change

1399行 `_list_hint(v, "change")` → 1196行 `l.text = String(pair[1])` の経路。
こちらは `change` 自体が辞書に未登録。連結とは別の登録漏れである。
`back` と `your settings` は単独の文字列として辞書に一致するため、画像どおり日本語になる。

## 確認結果

導入済み `volleyball.pck` を読み取り、次を確認した。

- `cfg_panel.gdc` のハッシュは、現在の配布用スナップショットとローカルのコンパイル済みファイルの両方に一致。
- 画像内の設定名8個と `on` / `off` は導入済み辞書に存在する。
- `change` と、画像内の設定名・値を連結した全文は存在しない。
- 導入済み辞書とゲーム実行ファイルを使った隔離したヘッドレス検証で、8項目すべての連結後の翻訳が英語のまま残った。
- 同じ実行で設定名と値を個別に翻訳してから連結すると、8項目すべてが日本語になった。
- 見出しは `あなたの設定`、戻る操作は `戻る`、`change` は英語になることも確認した。

実行結果は [evidence/controller-translation-investigation.json](../evidence/controller-translation-investigation.json)。
検証は翻訳照合の再現であり、実際の設定画面を操作した描画・レイアウト検証は行っていない。
ゲーム本体や既存セーブは変更せず、専用のユーザーディレクトリを指定した複製で実行した。

なお、導入済み辞書と現在の翻訳正本には `awards` / `create party` の2件の差があるが、今回の項目とは無関係。
調査対象の設定名を追加するだけ、または現在の翻訳正本をそのまま再適用するだけでは、この照合不一致は解消しない。

## 修正する場合

ビルド処理で `_value_row()` の初期表示と `text_fn` の両方に、設定名・表示値を
個別に翻訳してから連結する処理を追加する。内部の設定キーや保存値は変更しない。
`change` は翻訳正本に追加し、再生成・適用する。

同じヘルパーを使うスクロール下方の項目も影響を受けるため、設定値の切替後も日本語を維持すること、
長い日本語名が一覧の幅に収まることをあわせて検証する必要がある。
